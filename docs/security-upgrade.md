# 安全升级与一次性安装凭据

## 升级前

备份当前程序、`backend/.env`、本地极验允许列表与 SQLite 文件（正在使用 SQLite WAL 时应停服备份或用 SQLite 在线备份工具）。本 PR 不迁移已有数据库路径，也不轮换生产密钥。

所有机器人接口的路径、请求字段与成功响应保持原协议。默认 Key（最早创建的 API Key）用于管理后台；请在管理后台新建普通 Key 并填入插件。验证码校验必须同时匹配 API Key、群和用户，成功后原子消费。历史缺少 `api_key_id` 的验证码不会被放行；等待原有效期结束后重新生成链接。

## 新安装

1. 站点根目录必须是 `backend/public/`，禁止将整个 backend 暴露给 Web。
2. 在服务器 `backend/` 中，以 PHP 服务运行用户执行 `php think setup:token`（例如 Linux 上 `sudo -u www-data php think setup:token`）。凭据只在终端显示一次，服务器只保存 SHA-256，30 分钟有效。命令与 PHP 服务需要能读写同一组安装状态文件；不要将凭据放入 URL、日志、Git 或群聊。
3. 打开 `/setup`，填写凭据与配置，通过 POST 提交。未生成有效凭据或安装已完成时返回 404。重新运行命令会使上一凭据失效。
4. 数据库名只能使用字母、数字、下划线、短横线，首字符为字母或数字，名称最多 64 字符（不含 `.db`），以 `.db` 结尾，例如 `sqlite.db`。不接受绝对路径、目录、穿越或其他扩展名。
5. 初始化持有跨进程互斥锁，在临时数据库完成事务后原子发布数据库与最终 `.env`；不会覆盖已有文件。安装文件和目标必须支持同一文件系统内的硬链接。完整暂存后会写入哈希校验的安装恢复状态；如果进程在数据库和配置发布之间中断，下次入口检查会在持锁状态下完成这次已授权安装。普通失败可用尚未过期的凭据重试；凭据过期后重新生成。不要通过删除已有数据库来重试。

`.setup-token.json` 只保存哈希及期限，`.setup.lock` 用于互斥，`.setup-progress.json` 保存待恢复文件名与哈希；两者都在 public 目录外并已忽略。安装成功后删除凭据并留下 `.installed` 标记。删除 `.env` 不代表可以再次安装。

## 极验网关

默认只接受 `https://gcaptcha4.geetest.com`。自定义 HTTPS 网关需要服务器管理员在 `backend/config/geetest.php` 的 `allowed_origins` 或本地环境变量 `GEETEST_ALLOWED_ORIGINS` 中显式加入完整 origin（如 `https://captcha.example.com`，可用逗号分隔）。不接受用户名、密码、路径、查询参数或 fragment。网页设置不能扩大允许列表；已有未获允许的网关会停止调用，管理员应先核查来源再加入本地配置。

## 验证

在 `backend/` 内运行 `php tests/setup_security.php`，`php tests/pr1_http_security.php` 执行真实本地 HTTP 鉴权回归。测试使用隔离临时数据库，不连接真实极验和群聊。

原依赖 `zhaoyj/think-helper` 的源码已不可取得，原始锁文件安装会失败。鉴权 PR 的行为检查使用原锁的其余版本，隔离测试清单仅去掉该不可下载包；依赖升级 PR 会移除它并提交可重建锁文件。部署时应合入两个后端 PR 并执行升级后的生产安装。

## 回滚与上线

不自动合并、发布或部署。正式上线前复核备份，后端安全逻辑回滚可恢复上一程序版本与备份配置、数据库；安全修复回滚会重新暴露旧鉴权入口，不应继续公网提供服务。依赖回滚恢复上一版锁文件与对应正式构建产物。

真实群聊测试与全部 API Key 轮换留到部署阶段。如果旧后端曾暴露公网，部署修复后轮换全部 API Key，并核查极验 ID、密钥、网关及访问日志。
